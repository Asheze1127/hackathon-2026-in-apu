# 権限設計：Decision Path

---

## 0. 設計前提

| 項目 | 内容 |
| --- | --- |
| 権限モデル | RBAC（ロールベース） |
| マルチテナント | なし |
| 認証方式 | メールアドレス + パスワード / OAuth（Google 等）|
| スコープ単位 | Global |
| MVP 方針 | `USER` ロールのみで動作。`ROLE_MODEL` はハッカソンスコープ外のため将来対応 |

---

## 1. 用語定義

| 用語 | 意味 |
| --- | --- |
| Subject | 操作主体（ログイン済みユーザー） |
| Resource | 操作対象（LifeLog / RoleModel / Community 等） |
| Action | 操作内容（read / write / delete） |
| Role | 権限グループ |
| Policy | 判定ルール |

---

## 2. ロール定義

| ロール名 | スコープ | 説明 |
| --- | --- | --- |
| `USER` | MVP | 一般利用者（学生・社会人）。自分のログ管理・ロールモデル閲覧・AI チャットが可能 |
| `ROLE_MODEL` | 将来対応 | ロールモデルとして登録された人物。自分のキャリア情報の編集が可能 |

---

## 3. リソースごとの権限マトリクス（MVP）

### 3-1. LifeLog（人生ログ / 自分の木）

| アクション | USER（自分） | USER（他人） |
| --- | --- | --- |
| read | ✅ | ❌ |
| write | ✅ | ❌ |
| delete | ✅ | ❌ |

### 3-2. RoleModel（ロールモデル情報）

| アクション | USER |
| --- | --- |
| read | ✅ |
| write | ❌ |
| delete | ❌ |

※ MVP ではロールモデルデータはシードデータ or 運営が直接 DB 投入する想定。編集 API は実装しない。

---

## 4. MVP RBAC 判定ロジック

```pseudo
if not authenticated:
    deny (401)
else if resource.owner != user.id:
    deny (403)
else:
    allow
```

---

## 5. 将来の拡張（ハッカソンスコープ外）

| 拡張内容 | 概要 |
| --- | --- |
| ROLE_MODEL ロールの追加 | 申請 → 承認フローでロールモデル登録・自分のキャリア情報を編集可能に |
| ABAC による細粒度制御 | コミュニティの公開範囲（全体公開 / 目標コミュニティ限定）制御 |
| フォロー関係の権限 | フォロー中のユーザーのログを閲覧可能にする |

---

## 6. データモデル連携

| ルール | 参照カラム |
| --- | --- |
| ロール判定 | `users.role` |
| オーナー判定 | `life_logs.user_id` / `role_models.user_id` |
| アカウント有効判定 | `users.is_active` |

---

## 7. フロントエンド制御

| パターン | 説明 |
| --- | --- |
| 未ログイン時リダイレクト | `/login` へ遷移 |
| 権限不足時表示 | 403 エラー画面 |
| 他人のログ非表示 | 自分のログのみ一覧表示（MVP） |

※ フロントはあくまで UX 制御のみ。最終判定は必ずサーバー側で行う。
